## 業務ルール

<!--
書く: 計算・変換・検証、並び順、更新・削除対象、丸め、未設定値の扱い。入力・条件と期待結果の表で書く。
書かない: 内部の関数呼び出し、DBアクセス手順（必要時にコードから説明）。検証ケースの網羅はテストコードへ。
確認: 正常時・境界値・欠損・異常時の結果、変更するものと保持するものが分かるか。
表はテストケースではなく規則。テストはこの表の行を写して書く。
未決の行（境界値、欠けたデータ、異常系）は具体的な期待結果を仮案として記載し、未承認であることと理由を添える。PRコメントで動作例と代替案を示して採否を質問する。
Issue・PR・コードから独立して仕様を理解できるように書く。未実装でこれから実装が必要であることを示すメモは残さない。

例:
### 送料の計算

| 購入金額 | 送料 |
| :--- | :--- |
| 5,000円未満 | 500円 |
| 5,000円以上 | 無料 |
| 0円 | 仮定（未承認）: 注文不可。購入商品がない注文を防ぐため |
-->
