# 言語別パターン

AIが書いたコードで冗長になりやすい、言語ごとの典型パターンです。該当するものを削るか、より単純な書き方に置き換えてください。ただし、プロジェクトの既存規約がこれと異なる場合は規約を優先します。

## TypeScript

| 冗長なパターン | 置き換え |
| :--- | :--- |
| 推論できる型注釈（`const n: number = 1`） | 注釈を外す。公開関数の引数・戻り値の型は残す |
| 不要な `as` / `any` | 型を正しく付けるか、型ガードで絞り込む |
| 過剰なオプショナルチェーン（`a?.b?.c` で `a` が必ず存在する） | 存在が保証される箇所は `?.` を外す |
| 不要な `async` / `await`（Promiseをそのまま返すだけ） | `async` を外して Promise を返す。ただし `try` / `catch` 内で待つ必要がある場合は残す |
| 状態を持たないクラス | 関数にする |
| 値を列挙するだけの `enum` | 文字列リテラルの union 型にする |

## Go

| 冗長なパターン | 置き換え |
| :--- | :--- |
| 同じ文脈を何度も繰り返すエラーラップ | 文脈は呼び出しの一段ごとに一度だけ足す |
| 実装側で定義した、利用側が必要としていない interface | interface は利用側で必要になったときに定義する |
| Java風の getter / setter | 公開フィールドにするか、意味のある操作をメソッドにする |
| 並行性の必要がない goroutine | 同期的に呼ぶ |
| `if err != nil { return err }` の後の冗長な `else` | 早期returnにして `else` を消す |

## C#

| 冗長なパターン | 置き換え |
| :--- | :--- |
| 差し替えの必要がないのに作られた `IFoo` インターフェース | 具象クラスを直接使う。テストのモック境界・DIの差し替え点は残す |
| 過剰なDI層（委譲するだけのサービス） | 委譲先を直接注入する |
| nullable 有効下での冗長な null チェック | 非nullable型への null チェックを外す。公開APIの境界は残す |
| `#region` | 外す。分けたいほど長いならクラスを分割する |
| 値を詰めるだけのクラス | `record` にする |
